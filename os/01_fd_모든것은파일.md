# fd (file descriptor): "모든 것은 파일"

> 필요한 주제: 1 Event Loop. [01_C문법_최소가이드.md](../01_C문법_최소가이드.md) 0-1절을 더 자세히 쓴 것입니다.

## 1. 한 줄 요약

프로세스가 커널에 무언가(파일, 소켓, 파이프 등)를 열어 달라고 하면, 커널은 그 대상을 직접 넘겨주지 않고 **번호표(작은 정수)** 를 줍니다. 이 번호가 fd입니다. 이후에는 "7번에서 읽어 줘", "7번에 써 줘"처럼 번호로만 부탁합니다.

## 2. "모든 것은 파일"의 진짜 뜻

"모든 게 디스크에 있는 파일"이라는 뜻이 아닙니다. 대상이 무엇이든 **여는 방법만 다르고, 읽고 쓰고 닫는 방법은 같다**는 뜻입니다.

| 대상 | 여는 시스템 콜 | 읽기/쓰기/닫기 |
|---|---|---|
| 디스크 파일 (RDB, AOF) | `open` | `read` / `write` / `close` |
| TCP 연결 (클라이언트) | `socket`, `accept` | `read` / `write` / `close` |
| 파이프 (프로세스·스레드 간 통신) | `pipe` | `read` / `write` / `close` |
| epoll 인스턴스 | `epoll_create` | (`epoll_ctl` / `epoll_wait`) / `close` |

Kotlin으로 치면 모든 대상이 `interface Fd { read(); write(); close() }`를 구현하고, 프로그램은 객체 대신 `Int` id 하나만 들고 다니는 것과 같습니다.

## 3. 커널 쪽 그림

```
Redis 프로세스의 fd 테이블 (프로세스마다 하나, 커널이 관리)

 [0]  → /dev/null
 [1]  → pipe            (stdout)
 [2]  → pipe            (stderr)
 ...
 [7]  → eventpoll       ← 메인 이벤트루프의 epoll
 ...
 [18] → socket          ← 6379 리슨 소켓 (IPv4)
 [19] → socket          ← 6379 리슨 소켓 (IPv6)
 [24] → socket          ← 방금 접속한 클라이언트
```

- fd는 이 테이블의 **인덱스**입니다.
- 새로 열면 커널은 **비어 있는 가장 작은 번호**를 줍니다. 그래서 fd는 0, 1, 2, ... 처럼 촘촘합니다.

## 4. 왜 Redis에 중요한가

1. **클라이언트 연결 1개 = fd 1개.** 연결 1만 개는 결국 "fd 1만 개를 지켜보는 문제"가 되고, 이걸 epoll 하나로 감시합니다([05](05_IO멀티플렉싱_epoll_kqueue.md)).
2. **fd가 작고 촘촘하니 배열 인덱스로 쓸 수 있습니다.** `eventLoop->events[fd]`로 HashMap 없이 O(1)에 찾습니다([02_이벤트루프_흐름지도.md](../02_이벤트루프_흐름지도.md) 3절).
3. **열 수 있는 fd 개수에 OS 제한이 있습니다**(`ulimit -n`, `RLIMIT_NOFILE`). 그래서 `maxclients`는 OS 설정과 엮입니다.
   - Redis는 시작할 때 `maxclients + 32`개까지 열 수 있도록 제한을 올려 보고, 실패하면 `maxclients`를 스스로 줄입니다. 32(`CONFIG_MIN_RESERVED_FDS`)는 RDB, AOF, 리슨 소켓 등 클라이언트가 아닌 용도로 남겨두는 몫입니다.
   - 이때 로그에 `...requiring at least N max file descriptors.` 경고가 찍힙니다. 운영에서 `maxclients`가 생각보다 작게 잡혔다면 이 로그부터 봅니다.
   - 이벤트루프 배열 크기는 `maxclients + 128`(`CONFIG_FDSET_INCR`)입니다. 기본 `maxclients`가 10000이라 10128이 되고, 이 숫자는 strace에 그대로 보입니다([05](05_IO멀티플렉싱_epoll_kqueue.md) 6절).

## 5. Redis 소스에서 어디에 나오나

| 위치 | 내용 |
|---|---|
| `ae.c` `events[fd]` | fd를 배열 인덱스로 사용 |
| `anet.c:615` `accept4(...)` | 클라이언트 접속 → 새 fd 생성 |
| `server.c:2710` `adjustOpenFilesLimit` | `getrlimit`/`setrlimit(RLIMIT_NOFILE)`로 fd 제한 올리기 |
| `server.h:162`, `server.h:226` | `CONFIG_MIN_RESERVED_FDS 32`, `CONFIG_FDSET_INCR (32+96)` |
| `server.c:3109` | `aeCreateEventLoop(server.maxclients+CONFIG_FDSET_INCR)` |

## 6. 직접 확인

실험 환경은 [README.md](README.md)를 보세요.

```bash
docker exec -u redis redis-os ls -l /proc/1/fd
```

실제 결과(8.0.6, 연결 없는 상태)에서 일부만 옮겼습니다.

```
0 -> /dev/null
1 -> pipe:[5637]
7 -> anon_inode:[eventpoll]     ← epoll도 fd
13 -> anon_inode:[eventfd]
18 -> socket:[6338]             ← 리슨 소켓
19 -> socket:[6339]             ← 리슨 소켓
20 -> pipe:[6340]               ← 내부 통신용 파이프 (여러 개)
```

디스크 파일이 아닌 것도 전부 fd 목록에 같이 들어 있습니다. 이게 "모든 것은 파일"입니다.

이번에는 연결이 늘 때 fd가 같이 느는지 봅니다. 터미널 두 개에서 각각 계속 붙어 있는 클라이언트를 엽니다.

```bash
docker exec -it redis-os redis-cli SUBSCRIBE ch
```

그다음 socket 개수를 셉니다.

```bash
docker exec -u redis redis-os sh -c "ls -l /proc/1/fd | grep -c socket"
```

실제 결과: 연결 없을 때 `2`(리슨 소켓 2개) → 클라이언트 2개 접속 후 `4`.

## 7. 여기서 멈춤

- **설명할 수 있으면 충분:** fd가 무엇인지, Redis가 왜 `events[fd]` 배열을 쓰는지, `maxclients`가 왜 `ulimit -n`과 엮이는지.
- **몰라도 됨:** VFS, inode 구조, 프로세스 fd 테이블 → 열린 파일 테이블 → inode로 이어지는 3단 구조, `dup`/`dup2`.
