# 소켓

> 필요한 주제: 1 Event Loop, 8 Replication.

## 1. 한 줄 요약

네트워크 연결을 fd로 다룰 수 있게 해 주는 커널 객체입니다. 서버에는 **두 종류**가 있습니다.
- **리슨 소켓**: 6379 포트에 하나. 데이터를 주고받지 않고 "새 연결이 왔다"만 알립니다. 문지기 역할입니다.
- **연결 소켓**: `accept` 할 때마다 클라이언트별로 하나씩 생깁니다. 이후 `read`/`write`는 이 소켓으로 합니다.

Java로 치면 `ServerSocket`(리슨)과 `accept()`가 돌려주는 `Socket`(연결)입니다. Tomcat도 구조는 같습니다.

## 2. 서버 소켓의 일생

```
socket()  →  bind(6379)  →  listen(backlog)  →  ┌─ accept() → 새 fd (클라이언트 A)
   리슨 소켓 만들기                             ├─ accept() → 새 fd (클라이언트 B)
                                                └─ ... 반복
```

## 3. 커널 버퍼: write 성공 ≠ 상대가 받음

커널은 연결 소켓마다 **수신 버퍼**와 **송신 버퍼**를 가지고 있습니다.

```
클라이언트 ──네트워크──▶ [수신 버퍼] ──read()──▶ Redis 쿼리 버퍼
클라이언트 ◀──네트워크── [송신 버퍼] ◀─write()── Redis 응답 버퍼
                         (커널 안)
```

- `read` = 수신 버퍼에서 꺼내 오기. 비어 있으면 읽을 게 없습니다.
- `write` = 송신 버퍼에 넣기. **실제 전송은 커널이 나중에 합니다.** 그래서 `write`가 성공해도 상대가 받았다는 보장은 없습니다.
- 클라이언트가 느려서 송신 버퍼가 가득 차면 `write`를 할 수 없습니다. 이걸 어떻게 처리하는지는 [04](04_blocking_nonblocking.md) 4절에서 봅니다.

## 4. backlog

`listen(s, backlog)`의 backlog는 "Redis가 아직 `accept` 하지 않은 연결을 커널이 몇 개까지 줄 세워 둘지"입니다.
- Redis 설정 `tcp-backlog`(기본 511)가 이 값입니다.
- 리눅스 `/proc/sys/net/core/somaxconn`이 이보다 작으면 커널이 잘라 버리므로, Redis가 시작할 때 경고를 남깁니다.
- 접속 폭주(배포 직후 커넥션 풀 일제히 연결 등) 때 이 줄이 넘치면 연결이 실패합니다.

## 5. Redis 소스에서 어디에 나오나

| 위치 | 내용 |
|---|---|
| `anet.c:508` `anetListen` | `listen(s, backlog)` |
| `anet.c:609` `anetGenericAccept` | 리눅스에서는 `accept4(..., SOCK_NONBLOCK \| SOCK_CLOEXEC)`(615줄), 그 외에는 `accept`(617줄). 받는 순간 non-blocking으로 만듭니다 |
| `socket.c:301` `connSocketAcceptHandler` | 리슨 소켓이 "읽을 수 있음"이 되면 불리는 콜백. 한 번에 `max_new_conns_per_cycle`개까지 accept를 반복 |
| `socket.c:440`, `445`, `455` | 연결 소켓에 non-blocking, `TCP_NODELAY`, keepalive 설정([14](14_TCP_기초.md)) |
| `server.c:2790` `checkTcpBacklogSettings` | somaxconn 경고 |

## 6. 직접 확인

[README.md](README.md)의 strace에서 이 줄을 봅니다.

```
accept4(18, {sa_family=AF_INET, sin_port=htons(44448), sin_addr=inet_addr("127.0.0.1")}, [128 => 16], SOCK_CLOEXEC|SOCK_NONBLOCK) = 24
```

- `18` = 리슨 소켓 fd. [01](01_fd_모든것은파일.md)의 fd 목록에서 본 `socket:[6338]`입니다.
- 돌려받은 `24` = 이 클라이언트 전용 연결 소켓 fd.
- `127.0.0.1:44448` = 클라이언트 쪽 주소와 포트.

## 7. 여기서 멈춤

- **설명할 수 있으면 충분:** 리슨 소켓과 연결 소켓의 차이, 커널 송수신 버퍼가 있어서 write 성공 ≠ 수신이라는 것, backlog.
- **몰라도 됨:** `sockaddr` 구조체 세부, Unix 도메인 소켓, `SO_REUSEPORT`, 소켓 옵션 전체 목록.
